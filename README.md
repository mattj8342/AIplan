## How to use the plan

1. Start at Week 1, Night 1 and work through one night at a time.
2. Save the result named in each task: code, notes, a working example, a commit, or an assessment outcome.
3. Change `- [ ]` to `- [x]` in [PLAN.md](PLAN.md) when that night's result is complete.
4. Use weekly reviews to catch up and adjust the next week. Course completion and exam dates depend on readiness.

This plan contains intended, unchecked tasks. Credentials and course completions are goals until earned. The linked project currently contains its design and synthetic-data specification; implementation is a planned outcome.

## Portfolio project

**[Revenue Variance Investigation Agent](https://github.com/mattj8342/revenue-variance)**

Investigate settled-spend changes, interchange mix, customer rebates, net revenue, and net revenue yield between comparable settlement months. Produce separate dollar-impact and basis-point rankings for customers, vendors, and interchange categories, with supporting figures and suggested investigations.

Use the existing repository's [business questions](https://github.com/mattj8342/revenue-variance/blob/main/docs/business-questions.md) and [thirteen-column synthetic data contract](https://github.com/mattj8342/revenue-variance/blob/main/docs/data-contract.md). Net revenue is interchange minus customer rebate; it is not profit. Calculate rates from aggregated amounts and preserve the agreed refund and denominator rules.

Version one is a local, read-only explanation agent using fictional data and verified calculations. The later sandbox extension adds:

1. SQL data and API integration.
2. Analysis → AI draft → human approval → sandbox investigation record, with saved workflow state.
3. Deployment of this project and automated checks on commits.
4. Continuing Python engineering practice throughout.

The analytical transaction data remains read-only. Operational records use a separate sandbox store. This learning-plan repository does not contain the project implementation.
